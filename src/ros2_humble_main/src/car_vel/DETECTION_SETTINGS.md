# 检测功能开关

设置页面的“检测功能开关”提供十项独立配置：火焰、烟雾、人脸、车牌、跌倒、打架、吸烟、热成像高温、M701 环境检测和二氧化碳超限告警。点击开关后自动保存，USB 相机、巡检及环境检测共用；进入设置页只读取状态，不启动任务。

## 开关的作用

- 关闭火焰或烟雾会停止该类别的框、结果和告警。两者使用一个共享模型，全部关闭后跳过其推理。
- 关闭人脸或车牌后，不执行相应检测/匹配，不生成新的识别记录，并清空旧显示缓存。模型首次启用时按需加载；已登记档案和历史记录保留。
- 关闭跌倒、打架或吸烟会停止相应分支。跌倒和吸烟共用人物姿态，打架保持独立。原识别页面的三个行为开关与设置页同步。
- 关闭热成像高温检测，不影响热图预览；停止高温判定、告警和新事件。原手动识别/巡检意图保留，重新开启后按新帧判断，旧事件不补发。
- 关闭 M701 会在下一次轮询释放串口、停止读取，页面显示“检测已关闭”。重新开启恢复连接及原有预热流程。串口配置保留，USB 不断电。
- 关闭二氧化碳超限告警仅停用相应告警，不影响 M701 数据。M701 关闭时二氧化碳告警一并暂停，但保留它自己的开关选择及阈值。

视觉/行为开关表示允许对应检测，仍需启动识别或巡检才运行。已运行时从下一轮处理应用。全部视觉检测关闭时，已有相机识别进程可能继续提供原图；不会继续执行已关闭检测。检测开关不改变机器人导航、遥控、SDK 或停车策略。

## 保存与接口

配置保存在小电脑 `~/.ros/robot_navigation/detection_settings.json`，重启后沿用。默认保持原功能开启；首次迁移会读取旧 `behavior.json` 的三个行为选择。迁移后统一配置为准，旧行为接口经网关同步，不能再通过单独编辑 `behavior.json` 覆盖它。

网关提供 `GET /api/detection/settings` 和 `POST /api/detection/settings`。写入只提交修改项及当前版本：

```json
{"changes":{"fire":false},"expected_version":3}
```

版本冲突返回 HTTP 409，页面重新读取实际状态，不自动覆盖其他页面的修改。离线或读取超时会禁用开关；配置损坏会明确报错并停用相关检测，需显式重新保存。配置原子写入，消费者读取同一文件，不向其他串口探测或发送运动命令。

`ROBOT_DETECTION_SETTINGS` 可指定统一文件路径；设置时必须让网关、YOLO、热成像、M701 和巡检管理进程使用同一路径。常规部署无需设置。

## 部署与验证

同步完整的更新代码后，正常停止后台，在小电脑执行：

```bash
cd /home/a/3dnav
source /opt/ros/humble/setup.bash
colcon build --packages-select car_vel lzp_service --symlink-install
source install/setup.bash
```

重新按原方式启动后台，浏览器强制刷新。检测依赖和模型未因本次开关功能改变；上一次新增吸烟模型仍须完整同步。

只读检查已保存配置：

```bash
curl -sS --max-time 5 http://127.0.0.1:8766/api/detection/settings | python3 -m json.tool --no-ensure-ascii
```

先在机器人停止时逐项检查：关闭后对应框/新记录消失，其他项目继续工作；关闭高温仍可看热图；关闭 M701 后显示停用且不再轮询；刷新或重启后选择不变。新开关、保存冲突、跨页面同步、停用状态和布局已有离线/浏览器回归；实际相机、串口及 Linux 完整构建需在小电脑确认。
