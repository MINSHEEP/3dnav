# 星玑 / 钢镚 ZSL-1 点足：本体选择

## 当前实现

设置页提供本体、机器人 IP、通信端口，以及钢镚本地网卡 IP 和独立物理限速。
配置保存于运行账号的 `~/.ros/robot_navigation/robot_body.json`。
默认星玑；已有配置损坏时禁止回退控制其他本体。两条狗各自配置会保留。

`launch_manager_service` 监督唯一底盘子进程；星玑沿用原 UDP 遥控、动作及状态协议，导航也通过该进程发送。
钢镚仅使用附件 ZSL-1 高层 SDK，不使用 ZSL-1W 或底层电机控制。
导航安全链仍为 Nav2 → `/cmd_vel` → velocity_arbiter → `/cmd_vel_safe` → 当前本体。
遥控使用现有 `/dog_remote/*` 接口，导航和巡检继续通过 `/dog_remote/ensure_standing` 确认。
不再在导航或建图 launch 额外启动 `cmdvel_bridge_ros2`。不要手动运行旧 SDK demo 或旧 UDP 桥。
建图页面点击开启键盘遥控时，会先显式请求所选本体站立并确认，然后才接受按键；因此也需要确认该本体安装参数。

厂商 SDK 四个 ZSL-1 库已在源码 `car_vel/lib/zsl-1` 中，与本次附件逐文件 SHA256 一致。
Python 扩展需要 Linux、Python 3.10；支持 x86_64/aarch64。此工作区 Windows 不能加载 Linux SDK。
许可证见 `GENISOM_SDK_LICENSE.txt`。

## 部署到小电脑

先保持机器人静止，结束巡检、导航与建图，并停止旧版常驻程序。同步整个修改后的源码。

```bash
cd /home/a/3dnav
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select lzp_interface lzp_service car_vel
source install/setup.bash
ros2 launch car_vel launch_manager.launch.py
```

无需重新编译厂商 `.so`；新的 ROS 接口和 Python/前端安装内容需要上面的三个包重建。
浏览器强制刷新设置页、遥控页。不要同时保留旧版本后台。

首次钢镚接入需在机器人端按附件 `docs/deploy.md` 配好 SDK 网络：

- 有线默认机器人 IP：`192.168.168.168`（按现场实际为准）。
- 小电脑接入该网络的网卡必须有可达地址，例如 `192.168.168.15`，不能直接填网页 Wi-Fi IP。
- 机器人 `/opt/export/config/sdk_config.yaml` 的 `target_ip` 应为该小电脑 IP，`target_port` 与页面本地接收端口一致（默认 `43988`）。
- 非默认 Wi-Fi 网段还需厂商文档规定的 `SDK_CLIENT_IP` 配置，该字段按文档填写机器人自己的通信 IP，不是小电脑 IP。机器人端配置需要厂家要求的重启后生效。
- 本次代码不会登录机器人、更改网卡或自动修改这些系统文件。

无需运行会自动站立/行走的 SDK demo 验证导入。可只做只读导入检查：

```bash
/usr/bin/python3 -m car_vel.zsl1_adapter
```

上面验证原生库、Python 扩展和所需方法能导入，不构建控制对象，不连接机器人或发送动作；不代表机器人通信已经成功。
若报缺少共享库，先用 `ldd` 检查报错库；附件要求 Ubuntu 22.04、Boost 1.74。页面应用会在隔离进程中等待实际连接状态。

## 切换操作

1. 在遥控页让旧本体趴下；退出遥控页以释放会话。
2. 结束所有巡检/路线/园区任务，并停止建图/导航程序（不是只暂停路线）。
3. 打开设置，选择本体，填写它的网络参数，点击“应用本体 / 重新连接”。
4. 后端先冻结旧本体的所有命令，确认旧进程退出，再连接新本体；确认连接后原子保存配置。
5. 页面“已保存”和“当前连接”应都显示目标本体。切换不会自动站立、不恢复任何旧任务。
6. 先低速遥控验证前后、横移、转向、停止与急停；再确认导航参数并重新确认初始定位。

旧本体失联且曾被控制时，不能证明已安全停放，后端会拒绝切换。先恢复连接并趴下；确需断电维护时，确认实物停放后停止常驻程序再处理，不绕过在线切换门禁。
从未连接、未收到控制请求的初始默认星玑可直接切换至钢镚。
新本体连接失败不会自动恢复旧本体或启动动作；修改参数后重新应用。切换途中失败或管理进程退出，需要人工检查当前本体。

## 钢镚行为与限制

- `move` 采用 m/s、m/s、rad/s，默认最高前后 0.5、横移 0.2、转向 0.6；不套用星玑 1.5 倍速度缩放。
- 20 Hz 输出，限制加速；零命令、0.3 秒命令过期立即清目标。遥控页面心跳超过 0.45 秒停车。
- 钢镚站立现在分为请求、等待、待命三步。`standUp()` 后至少等待 4 秒，并要求模式 1、机体速度各轴小于 0.03 m/s、角速度各轴小于 0.1 rad/s，连续满足 0.5 秒；最多等待 8 秒。这是基于附件示例的保守门禁，不是物理站稳证明，需在实机验证。
- 等待由定时器推进，不在 ROS 回调中休眠数秒；导航站立服务等待同一个结果再返回成功，并使用独立回调组，等待期间仍能处理急停与状态更新。
- 等待期间的行走命令不缓存、不重放；页面站立按钮附带的零速消息不会触发 Move。完成等待后必须收到新的运动命令。重复站立请求不会重置等待计时。
- 仅在本程序已经发送非零运动后，普通停止才发送 `move(0,0,0)`；站立待命不调用 Move 充当心跳，也不反复调用 standUp。SDK 实例及其内部通信保持运行；部署验收须检查持续待命不会掉线/进入阻尼。
- 停车、退出遥控、失联或低电量会撤销等待和授权；重新连接或复位不会自动站立、恢复行走。2026-10-20起，等待超时或SDK错误只锁定运动并尝试一次 `move(0,0,0)`，不再自动请求 `passive()`；原始码、模式、参数及零速失败原因仍保留。只有遥控紧急停止按钮/T键的显式emergency命令保留阻尼急停。SDK拒绝或失联时不能保证物理停车。
- 电量不高于 15% 时不允许开始/继续运动；SDK 文档警告低电量可能直接断电。
- SDK 文档说明失去 SDK 通信约 3 秒会自动阻尼趴下，SDK 占用时手柄不能正常接管。进程退出/系统关机前必须安全停放。
- 首版不提供星玑的高速/越障切换、厂商停障开关和特殊动作；页面禁用且后端拒绝。普通 ROS 障碍检测、代价地图与速度仲裁保留。
- ZSL-1 控制模式是最后执行模式，不等同真实姿态；没有完整硬件故障汇总时页面显示未知，不能将“连接正常”当作硬件自检通过。
- 普通地面上的 2D/3D 导航可复用。坡道、楼梯、粗糙地面等专用运动模式未验证，后端明确拒绝，不伪装成支持。

## 导航安装参数确认

相机、热成像、气体检测、YOLO、语音和地图数据沿用现有配置。本轮不猜测钢镚的体型/安装尺寸。
首次钢镚导航默认锁定。现场必须核对机器人碰撞轮廓、雷达到机体外参、离地高度与导航速度；参数不同先改配置、重建，再在页面确认。
当前几何配置仍是这一台小电脑的一套配置，并非自动保存两套 URDF/足迹。若两条狗尺寸或传感器安装位置不同，应在每次更换时重新配置、验证，不能勾选后直接使用。
页面确认只允许开启导航，不自动改变足迹、不缩小安全距离、不将 SDK 里程计覆盖现有 LIO/TF。

## 最小验收

- 星玑回归：站立、遥控/按键松开停止、导航转向连续性、急停与原动作。
- 钢镚：先趴姿连接，确认切换不自动站立；再站立后低速行走、转向、松键、关闭遥控页面，最后急停/复位。
- 运行/暂停任务、遥控会话未退出、旧狗站立/失联、新 IP 错误、SDK 缺失时检查切换拒绝原因。
- 确认当前本体是唯一 `/cmd_vel_safe` 硬件订阅者；重复启动旧入口应报硬件控制已占用。
- 验证网络中断后不继续走，恢复网络后不自动恢复；在安全支撑/人员隔离下执行，保留实物停止手段。
- 最后在已验证的平地测试 2D、3D 导航和巡检，以及 USB/热成像、气体阈值、语音告警回归。

以上实物与 ROS2 Linux 联调不能由 Windows 离线测试替代。

# 建图定位暂停（星玑与钢镚）

建图时，LIO 的定位异常根据当前本体走各自独立的暂停话题，不作为机械狗硬件急停。星玑本体桥持续发送零速度并阻止移动；钢镚停止行走时使用 SDK `move(0,0,0)`，不主动切换到 `passive()` 阻尼模式。健康扫描恢复后，两款本体都会清除旧速度指令，钢镚还需重新确认站立/稳定反馈才能继续移动。钢镚若仍处于 SDK 行走模式，会等待至少 4 秒和连续静止反馈，无需先执行阻尼急停或重复 `standUp()`。

星玑建图遥控在短暂 LIO 软隔离后，若此前已确认站立、本体状态仍新鲜且无真正急停，会保持遥控页面的启用状态；页面明确确认所有方向键已松开、控制链也收到零速度后，再按新方向键即可继续，不必重开遥控模式。速度仲裁器自行生成的超时零速度不能代替页面的松键确认。关闭遥控、页面失焦/隐藏会撤销建图遥控授权；通信失联、姿态变更或真正急停后也不自动恢复，需重新确认站立。

2026-10-20起，公共 `/motion_stop` 及兼容旧 `/emergency_stop` 均只请求零速并锁定运动，不再触发本体硬急停。LIO确认故障也走 `/motion_stop`；临时恢复仍沿用独立软暂停通道。只有遥控按钮/T键的 `/dog_remote/command` 中 `command=emergency` 保留原生硬急停。建图开始前按已选本体确定话题路由；建图中不能切换本体。

部署时安全停止任务，同步重建 `car_vel`、`small_point_lio` 和 `lzp_service`，重新加载工作区并重启唯一主后台；仅刷新网页不生效。定位持续失效时继续保持零速门禁，应检查雷达、IMU与点云匹配，不能自动继续建图。钢镚零速若被SDK拒绝，只记录错误并锁定，绝不自动改用 `passive()`；需要人工检查，不能视为已经物理停稳。

## 2026-10-20：人工硬急停与软件停车的边界

- 普通切页：单点目标取消并发送零速，不锁本体、不主动趴下；遥控仍须等后台确认导航/建图核心已停止后才开放控制。
- 定位连续跳变、LIO确认故障、园区连接段异常、SDK异常：请求零速并锁定运动；新目标、定位恢复、普通站立或健康心跳不会清锁。公共停止话题还取消当前导航及未完成预览，保存路线不删除，人工解锁后也不续旧任务。
- `emergency_latched` 为兼容的通用运动锁字段，不能据此认定已发硬命令。`hardware_emergency_latched` 仅显式人工硬急停为true；`stop_kind` 区分 `manual_emergency` 与 `zero_speed_latched`。
- 人工R或导航页确认解除停车锁均会清除旧速度；软锁复位不发送星玑CMD4、不自动站立，后续必须重新确认控制/导航。人工硬急停复位保留原有CMD4语义。
- 保留的emergency命令是ROS接口约定，不是用户身份认证；其他节点不得将其当作自动故障停车接口。厂商固件内部保护或通信失联后的本体行为不受此改动控制。
